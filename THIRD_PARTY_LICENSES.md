## Map data and tiles

Map data © OpenStreetMap contributors, licensed under the [Open Database License 1.0](https://opendatacommons.org/licenses/odbl/1-0/). See [OSM copyright and attribution](https://www.openstreetmap.org/copyright) and [attribution guidelines](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines). The interactive map shows a visible attribution link on desktop and mobile. Derived database redistribution may trigger ODbL share-alike requirements; a software library's license does not replace the geographic data license.

Maps use MapLibre GL JS (`maplibre-gl` 5.x) with [OpenFreeMap](https://openfreemap.org/) Liberty by default (`https://tiles.openfreemap.org/styles/liberty`); the alternate style is labeled Light (`https://tiles.openfreemap.org/styles/bright`). `VITE_MAP_STYLE` optionally supplies an http(s) or root-relative style URL, not a `mapbox://` URL. OpenFreeMap requires OpenStreetMap and [OpenMapTiles](https://openmaptiles.org/) attribution supplied by the style sources; keep these linked credits visible on desktop and mobile. No Mapbox renderer logo is required. Retain applicable OpenMapTiles [license and attribution notices](https://github.com/openmaptiles/openmaptiles/blob/master/LICENSE.md) and any custom style/source notices; the renderer's BSD-3-Clause license does not replace data or service terms.

OpenFreeMap’s public service requires no routing API key and offers no SLA. Styles, fonts, sprites and tiles are browser-direct requests to OpenFreeMap or the configured style’s providers. No backend or offline basemaps are added, and the service worker does not cache or intercept basemap resources for offline use. `VITE_ORS_API_KEY` is solely for browser-direct hosted OpenRouteService cycling/hiking routing; a missing key disables automatic routing, not the map, manual planning, saved routes or GPX. No Google or Apple map content is used.

The documented mode uses coordinates or map clicks/draggable pins only; address/place search APIs, paid geocoding and terrain services are not used. There is no replacement search provider, new API or proxy.

## Routing and imported GPX elevations

New routes use [hosted OpenRouteService directions](https://openrouteservice.org/dev/#/api-docs/v2/directions/) profiles `cycling-regular` and `foot-hiking`, with the application’s unchanged 2–25 input-point limit. Requests are POST `https://api.heigit.org/openrouteservice/v2/directions/{profile}/geojson`, using `Accept: application/geo+json`, `Content-Type: application/json`, `Authorization: <API key>` and body `{ "coordinates": [[longitude, latitude], ...], "instructions": false, "elevation": false }`. The endpoint requires the GeoJSON response media type; `Accept: application/json` can return HTTP 406 (ORS code 2007). Responses are GeoJSON FeatureCollections containing LineStrings and distance/duration summaries. Geometry-derived statistics remain unchanged. Profiles are not certified gravel/trail access recommendations. The app routes triangular intermediate-point candidates, adjusts radius, and makes at most six calls across two orientations. Length and uniqueness are approximate; surface/access suitability is not guaranteed.

Terrain-RGB fetching, decoding, sampling and caching are entirely excluded. ORS directions request `elevation: false`; no route elevation enrichment is performed. ORS and legacy Mapbox routes hide ascent/descent statistics and the elevation chart, including old snapshots with sampled heights. Only imported GPX with complete heights at every track/route point and at least two samples retains elevation statistics/chart, including saved GPX snapshots. GPX with missing or partial heights hides these controls; existing heights are preserved for export, never filled or treated as zero. GPX height accuracy and redistribution permissions depend on the imported data’s source. Surface breakdown is unavailable.

IndexedDB version 2 cleanup retains supported `openrouteservice`, legacy `mapbox`, `gpx` and `manual` sources and removes unsupported retired-provider records. New online snapshots use `source: openrouteservice`; save, duplicate and reopen preserve source and exact geometry. ORS GPX exports credit openrouteservice and OpenStreetMap contributors, linking to [openrouteservice](https://openrouteservice.org/) and [OSM copyright](https://www.openstreetmap.org/copyright). Legacy Mapbox exports retain Mapbox/OSM attribution and their original provider terms. Manual and imported GPX exports do not claim routing-provider attribution. Provider results are not relicensed as ODbL data by this application. **Before publication independently verify current [ORS terms](https://openrouteservice.org/terms-of-service/), [restrictions](https://openrouteservice.org/restrictions/), account eligibility, commercial use, permanent storage, caching, GPX export/redistribution and attribution requirements.** Retained Mapbox snapshots remain subject to [Mapbox terms](https://www.mapbox.com/legal/tos) and [product terms](https://www.mapbox.com/legal/product-terms). Local-save/export decisions and provider migration do not grant redistribution rights.

## Privacy

Routes stay in local IndexedDB. The last map center/zoom/bearing/pitch, selected language and theme stay in localStorage. Translations and Onest fonts are bundled locally; no translation services or font CDNs are contacted. First-visit starting regions use browser timezone/language without IP lookup, external inference services or automatic geolocation permission requests; they are not measured user locations. User-selected routing points go browser-direct to `https://api.heigit.org/openrouteservice` with the API key in the Authorization header. OpenRouteService receives routing requests and the browser’s network address; [ORS privacy policies](https://openrouteservice.org/privacy-policy/) apply. Basemap providers receive style/font/sprite/tile requests and the browser’s network address under their respective policies, without the routing key. No address/place searches or terrain requests are sent. There is no application backend or proxy processing route data. Hosting access logs/privacy policies are the deployer’s responsibility. Optional location access occurs only when requested. No analytics, authentication, OAuth or cloud route synchronization are added. No Mapbox routing traffic is required; legacy Mapbox snapshots remain local.

The application deploys as static frontend assets with SPA fallback at the origin root, not as a server API. Configure `VITE_ORS_API_KEY` only if routing is needed, and optional `VITE_MAP_STYLE` (http(s) or root-relative style URL) in gitignored `client/.env` or `client/.env.local`. The routing key is trimmed and must be nonempty; no Mapbox `pk.*` prefix is required. **The ORS API key is visible in browser requests and built assets. Never commit actual keys.** Direct browser access cannot keep the key secret or prevent reuse and quota abuse; no server-side rate limits exist. Monitor daily/per-minute quotas in the [HeiGIT account dashboard](https://account.heigit.org/). Production shared/public applications should use a server proxy with a server-held key and rate limits; no such proxy is implemented here. Missing the key disables automatic routing/loops only. The offline service worker supports the static shell, local library, manual calculations and GPX workflows, not basemap or provider-response caching.

Review current hosted ORS quotas and restrictions before deployment; successful routing is not a production availability, future eligibility or unlimited-free-use guarantee. Browser request bounds and the five-minute/20-entry in-memory response cache are not account-wide usage controls. OpenFreeMap’s public basemap service has no SLA. No quota-management UI is provided. Successful requests and provider migration do not establish permanent storage, caching or GPX export/redistribution rights. Automated tests use synthetic responses and non-real keys and do not claim live provider or legal verification.
