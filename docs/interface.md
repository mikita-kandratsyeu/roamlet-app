# Interface, branding and accessibility

## Planner layout and accessibility

The application has a minimum layout width of 320 CSS pixels, including the library and comparison screens. Narrower browser windows produce horizontal scrolling instead of further shrinking the layout.

On mobile (up to 700 px), the planner has three sizes: a compact route header, a planning panel balanced with the map, and an expanded editing panel. Tap the header to show/hide planning, use the separate expand/restore button, or swipe vertically on the header to move one size at a time. Swiping the planner content still scrolls it, not the sheet. Focusing a text field expands the panel to give editing more room; the map remains visible. On short screens the two open sizes share the available height. Compact mode hides the content and footer, retains the route summary and preserves inputs; reopen the panel for save/export/import. Its summary uses personal total time when available and flags outdated routes instead of presenting stale statistics. Panel collapse retains the existing local preference; the expanded editing size is temporary. On desktop and mobile, the footer keeps the labeled Save route action and 44 px export/import icon buttons on one row. Both icon actions retain accessible names and tooltips; import remains available after planning. While importing, a spinner, announced status and a cancel icon preserve the existing cancellation flow.

Desktop route statistics keep distance and the original time estimate side by side, stacking them when the summary is 280 px wide or narrower. Personal moving time and total time with stops each occupy a full-width row when stops add time; with no stops, the identical estimate appears only once. Mobile shows distance and the personal time first; “More statistics” reveals the original estimate, personal moving time when distinct, planning reference and available elevation metrics. If personal time is unavailable, the original estimate remains visible. Labels, values and the explanatory note share consistent left alignment. Long time ranges wrap between complete duration values on narrow screens; calculations and stored statistics are unchanged.

The planner shows a compact, non-interactive **Not saved** badge below the route title for unsaved edits, with **Unsaved changes** as its tooltip. Saving removes the badge; subsequent edits restore it. Recalculation warnings retain their explanatory text instead of the badge. The badge supports English/Russian and light/dark themes.

Route stop actions adapt to the number of available buttons: one fills the row, two share it equally, and both layouts show icons with text. With three actions, Add a stop retains its label while Reverse and Clear stops remain icon buttons with accessible names and tooltips.

“Report a map issue” is available in the map’s “More map tools” (⋯) menu on desktop and mobile, rather than as an overlay on the map.

**Color route by slope** is also in this menu, off by default. When enabled, the menu shows a labeled blue-to-green-to-yellow/orange/red legend for downhill, flat (−1% to +1%) and uphill sections. The toggle uses a bordered card with a separate icon, a wrapping label, explicit enabled/disabled text and a decorative switch indicator. Its active state uses a subtle theme-aware tint rather than a solid filled action. It supports keyboard activation, English/Russian, light/dark themes and reduced motion. It is unavailable without any drawable section with known saved GPX/confirmed OpenRouteService heights, while geometry is stale, or in comparison/detour mode. Partial tracks color only known-height runs, preserving original styling on unknown/manual sections. ORS slopes carry a terrain-estimate notice. The selection is temporary, survives basemap changes and valid-route updates in the current map, and is not saved in preferences, routes or GPX. Coloring disappears for unavailable/stale geometry and returns when usable current geometry is available again. Existing arrows, markers, direct-line styling, climb selection and provider attribution remain unchanged. See [slope calculation limits](planning.md#route-slope-coloring).

Keyboard focus on buttons, links, dropdown triggers, checkboxes and sliders uses a clear 2 px theme-aware outline. Text, number, date/time and multiline fields retain an accented border and a soft 3 px halo while editing, including after touch input; invalid fields keep their error color. Search highlights its whole container without a second ring on the inner field. Pointer taps do not force keyboard-only outlines on buttons. Modal button outlines sit inside the button to avoid clipping in scrollable content; filled actions use their contrasting text color. Forced-color mode uses system outlines instead of relying on shadows.

Scrollbars share the planner's thin thumb and transparent track throughout the app, including dialogs, menus, library and comparison screens. They follow the active color theme and use system colors in forced-color accessibility mode. Dialog headers and their close buttons stay visible while only the content scrolls on desktop and mobile. Standard desktop dialogs leave an 8 px gap between the header and content. Close buttons share the header’s top-right alignment and a 44 × 44 px touch target, including compact confirmations with multiline titles or descriptions. On mobile, full-screen dialog headers use the same 20 px horizontal inset as the content, with titles vertically centered beside the close button; compact dialogs remain centered cards. The mandatory first-visit disclaimer uses the shared compact dialog, with its safety text in a theme-aware information panel and a focused acknowledgement action.

**Menu → Connections** groups Google Drive/GitHub under **Backups** and Google Calendar under **Calendar**, without search or filters. Cards share a responsive two-column desktop / one-column mobile layout and one primary setup/management action, sized to its label on desktop and full-width on mobile; connection failures replace it with Retry while keeping settings as a secondary outlined button beside it on desktop and below it on mobile. Google Calendar uses the same accessible dialogs, independently of backup connectors. Its connection dialog shares the Google Drive dialog width, account-summary styling, collapsed privacy section and fixed Done footer. Calendar and ICS actions occupy the full available planner width, with the existing outlined button style and 44 px minimum touch target. The schedule keeps one departure editor across timing edits and route switches. Publishing and opening linked events live inside **Route schedule**, not map controls. Google-specific route actions appear only after connection, stay available for reconnecting after expiry/network failures and disappear after explicit disconnect. The independent ICS action remains available without a connection. The event preview groups the route title, localized start/finish dates and times, explicit IANA timezone/UTC offsets, location and the exact description in one card. Timezone and reminder fields share a responsive settings section, with initial keyboard focus on timezone. Timing/privacy explanations start collapsed, while the local-only or Google-sharing notice remains visible. The fixed footer makes the offline ICS action primary and full-width when no Google action is present. Saving the current route is required for Google publication, but not for ICS. See [Calendar connections](connections.md#google-calendar).

## Application version

The header's **beta** marker has a small native browser tooltip showing the current application version in English/Russian. Its version comes from the root `package.json`; keep the root and client package versions aligned when releasing.

## Planner status and notifications

The expanded empty mobile planner shows its starting guidance only in the status block; its collapsed header retains the guidance. Informational/success notifications without actions do not intercept clicks on underlying controls, while their dismiss buttons remain usable. They stay below open application dialogs so export/save controls remain reachable; error/warning notifications and notifications with actions remain interactive.

## Branding and languages

All shared dialogs use the close-route confirmation's typography: 18px/650 titles with 1.3 line height, 14px/400 descriptions and body copy with 1.55 line height, and 14px/600 action labels with 1.45 line height. Compact, standard, wide and mobile dialogs share these rules; mobile text fields stay 16px to prevent focus zoom.

User-facing Help describes planning, local storage, offline limitations, GPX exchange, approximate time/elevation and online data flows in English and Russian. It credits OpenStreetMap/ODbL, the Standard OSM and Light OpenFreeMap/OpenMapTiles maps, and OpenRouteService/HeiGIT; custom-source attribution stays on the map. Help and routing errors do not instruct users to obtain keys, configure servers or manage provider accounts. Deployment instructions remain in this README. Help is not a legal compliance guarantee or a grant of additional data rights. Library no-results states explain search/filter recovery in both languages; The no-results action “Reset search and filters” clears all active filters as well as the query.

The interface follows the [Figma reference](https://www.figma.com/design/Bnb9WjC8w59XeZbZdfvtjl/Roamlet-App?node-id=0-1&p=f&t=8dArWhSgsLrTVNyz-0): 420px floating desktop planner, segmented activity/mode controls, elevation profile inside the planner at every screen size, mobile bottom sheet, a separate library screen with “Back to map”, and shared save/confirmation dialogs. `client/src/planner.css` supplies the responsive layout; `client/src/components/ui/shadcn.css` supplies the shared light/dark palette. Existing Roamlet artwork, wordmark and application icons remain unchanged. No Mapbox renderer logo is required; geographic data attribution remains visible. Map tiles, routes, markers, and elevations remain live geographic data rather than the reference's demonstration artwork. Bottom map actions share a wrapping toolbar; its measured height and provider attribution reserve space for compact map controls. The compact style picker moves below the planner-reopen action after resizing, so map overlays do not cover each other or provider branding.

Roamlet uses a restrained forest-green accent, neutral light/dark surfaces, and a winding-path brand symbol. The desktop header exposes route creation directly; saved routes are available in the menu on desktop and mobile. On mobile, route creation joins saved routes, preferences and help in the compact menu. The map fills the desktop workspace behind a collapsible floating planner. The planner scrolls vertically only, with width-constrained content and elevation charts at every screen size, including offline mode. Its route title and collapse control remain fixed above the scrolling content on desktop and mobile, with an opaque theme-aware background and a thin divider; guidance and route controls scroll underneath. Current route statistics and the elevation profile appear before personal-time settings. Personal-time settings, climb analysis and the route schedule start collapsed; expanding them preserves their inputs and map interactions. These disclosure states persist during personal-time edits and language changes and reset when a different route is opened. A single status block below the route heading reports unsaved/saved state, calculation, stale geometry or actionable routing errors; errors retain retry, manual-drawing, library and dismiss actions. When the planner is hidden, routing errors remain available through the global notification. Mobile uses a separately scrollable bottom sheet, persistent save/export actions, and a one-tap collapse control, keeping the map usable. Typography uses [Manrope from Google Fonts](https://fonts.google.com/specimen/Manrope), a geometric sans-serif with Latin and Cyrillic support and variable weights 200–800. It is self-hosted through Fontsource under SIL Open Font License 1.1, so the interface, forms, and map controls use one family without external font requests. Brand colors are CSS custom properties. English and Russian interface copy uses concise route terminology, actionable empty states and errors, and clear save/import/export guidance rather than generic adventure slogans. The browser title and page description follow the selected language.

English and Russian translations use i18next and react-i18next with JSON dictionaries in `client/src/locales/en.json` and `client/src/locales/ru.json`. Edit these files to update translations; keep their keys and interpolation placeholders aligned. Both dictionaries are statically bundled, so translation loading works offline without extra network requests. The desktop header provides separate “New route” and menu controls; mobile retains only the menu, with “New route” available inside. “My routes” is available in the menu on both screen sizes without a duplicate navigation button. The menu follows the Figma preference panel: matching left-aligned route/library/reset/help icon actions with consistent typography and spacing, section labels, right-aligned language checks and highlighted selections, plus local-storage and map-context notes. It offers library access, language, appearance, and help. It supports keyboard navigation (arrows, Home/End, type-ahead, Escape/Tab), outside-click dismissal, and focus restoration; unsaved-route confirmation is preserved. Select the language in this menu; the choice is stored locally and updates the document language, interface, accessibility labels, and locale-aware statistics. First visits use the browser language with English fallback. User-entered route names/descriptions and geographic place names are not translated. Changing language does not recalculate routes or reset the map. Translations and font assets remain available in the offline app shell.

UI controls use [shadcn/ui](https://ui.shadcn.com/) with Radix accessible primitives and Tailwind CSS: buttons, text fields, labels, activity/route-style toggle groups, the distance slider, dropdown menus, dialogs, cards, notifications, loading skeletons, and the interactive elevation chart. Components live in `client/src/components/ui`; `client/components.json` configures the registry. Sonner reports route calculations through one reusable loading toast that becomes success or error; cancelled and superseded requests never produce stale completion notices. Routing error details and the retry action appear only in the toast. The planner retains persistent previous-route context and disabled save/export controls, but no duplicate error text, recovery buttons or loading banner. Saving a route and library edits, deletion, duplication, backup import and export use promise toasts covering the operation and list refresh. Library errors appear only in Sonner, without duplicated messages inside import/edit/delete dialogs; retry controls and focus remain available after a failed operation. Action locks and inline validation remain. Initial map loading uses the global map loader; comparison maps keep their loader inside the map without blocking the surrounding screen. Both show a calm themed background, one animated route trace and a single loading message instead of a spinner and progress bar. Reduced motion shows a static route. Optional full-screen panel loaders use the same visual and preserve their Back to map action. Initial library reads and load retries show an inline, themed skeleton with four decorative route-card placeholders, two columns on desktop and one on narrow screens. An accessible status explains that routes are being read from this browser, without showing a fake route count or empty-library message. Reduced motion disables the skeleton animation. Back to map and Escape remain available during loading, and search receives focus when loading finishes. Library mutation refreshes retain the existing promise toast and cards rather than switching to the initial-loading skeleton. Backup export confirms that the browser download started, not that the file was saved to disk. MapLibre GL JS supplies map rendering, style-source attribution and draggable geographic markers; zoom/location/fit controls use shadcn buttons. OpenFreeMap requires OpenStreetMap/OpenMapTiles attribution supplied by the style sources, not a Mapbox renderer logo. The planner guides activity → routing mode → coordinates/map → stops → route overview → save/export. GPX import is offered in the planner only; the map no longer duplicates this action. Stops are reordered with labeled up/down buttons; drag grips are omitted to leave more room for stop names and coordinates. Selection uses a thin primary-color border and a subtle tint across the entire card, while keyboard focus remains on the stop button without a colored text pill. Replacing a stop from its card or map action prefills latitude and longitude with its actual coordinates without rounding. Switching the replacement target resets the fields and validation errors; cancellation clears the fields without changing the route. Automatic point-to-point routes still calculate through Directions; a prominent calculate/update action also retries failed requests. Manual is a map tool, not a route-style tab: its sole activation control is a ruler-icon button in `map-extra-controls`, alongside zoom, geolocation and fit controls. While the manual tool is active, the automatic “Point-to-point”/“Round trip” selector is hidden and the planner shows a short, noninteractive straight-line/no-snapping hint. “Undo last point” appears immediately after the ruler in `map-extra-controls`, only while manual mode is editable. Desktop controls keep north, zoom, locate, fit route, ruler and history actions available. Above 700px, the map-style picker sits in the bottom-right map corner above attribution; the elevation profile remains in the scrollable planner and hides with it rather than covering the map; the 701–1024px floating planner starts at the standard top spacing instead of reserving an empty top strip. At 700px and below, the picker stays at the top, below the planner-reopen button when present. Explicit route fitting accounts for the picker's top/bottom position. At widths up to 700px, only location, fit route and “More map tools” remain in a compact themed toolbar. The extra-tools panel contains north, zoom, drawing, history and the map-issue link, with 44px touch targets, keyboard focus, Escape/outside-click dismissal and a straight divider above the link. The ruler uses primary-theme styling when pressed. The map drawing hint is informational only and remains hidden in compact layouts. Help distinguishes manual straight lines from routed paths: manual planning supports up to 1,000 editable points, does not snap to roads/trails or validate network connectivity or access, and needs no Mapbox token. Adding, moving, reordering, removing, or recalculating points preserves the map camera. Automatic route fitting is limited to opening/importing a route; “Fit route” remains an explicit action. “Use my location” shows a blue location dot and recenters the map at zoom 14 without zooming out an already closer view; it never adds a stop. Repeated requests update the same dot, which remains visible when switching map styles. Mode switches that replace existing geometry require confirmation. Enabling a round trip retains only the start point after confirmation, as before. A compact definition list presents real route metrics. On small screens, distance and the original time retain visible labels in two columns; additional metrics use full-width rows with right-aligned, unbroken time ranges and straight separators, without hiding values or changing calculations. Ascent/descent statistics and the collapsible elevation profile are shown only for imported GPX geometry with complete heights at every track/route point and at least two samples, including its saved snapshots. Manual routes, Mapbox routes and GPX with missing or partial heights hide both elevation statistics and the entire chart on desktop and mobile; missing heights are never filled or treated as zero. Its header has a dedicated chevron toggle; metre units appear on the chart axis rather than beside the toggle. Imported GPX and saved Mapbox/GPX snapshots show a geometry-preservation notice with a separate full-width outlined “Edit waypoints” action, matching the Figma reference. Saved manual routes reopen with their exact points directly editable, without rerouting. Empty routes show next-step guidance rather than meaningless metrics. The library uses a compact list with favorites, filtering, editing, duplication, deletion confirmation, and offline/device-storage management. Saved descriptions are clamped to two lines in library cards. Tags appear below the planner description using the same first-three-tags-plus-overflow preview as library cards. Long preview labels are ellipsized; clicking the planner tag row opens the full route view with every tag, including routes without a description. Tag backgrounds, text and overflow colors use shared theme tokens in the library, planner and full view. Nonempty route notes also appear as a two-line preview beneath the planner heading; clicking the preview opens the complete plain-text description in an accessible dialog and restores focus on close. Empty descriptions add no UI, and notes do not overlay the map or expand the collapsed mobile sheet.

Transient notifications use a shared shadcn/ui Sonner toaster: route save/import feedback, routing/map failures with recovery actions, settings/storage errors, library operations, and app-update notices. Success messages close automatically; errors remain until dismissed or resolved. Error toasts use a subtle destructive-tinted background, border and icon in both themes, with readable neutral text; their retry button sits below the message rather than squeezing it into a narrow column. Routing-unavailable copy states the cause and next step briefly. Toasts follow the active language and theme and remain available when the planner is hidden or the library is open. Their width is capped at 400px and shrinks to fit narrow screens with safe-area spacing; multiline text wraps beside a top-aligned icon, and the inset dismiss control has a 44×44px touch target. Field validation and persistent route/offline guidance stay inline.

Coordinate entry uses separate labeled **Latitude** and **Longitude** text fields with decimal examples and inline, localized validation. Paste a latitude/longitude pair into either field to distribute it automatically; pairs accept a comma separator with dot decimals, whitespace, or a semicolon (including decimal commas). A single decimal-comma number remains in one field. Signed values, including negative coordinates, are supported; latitude is limited to −90…90 and longitude to −180…180. Enter or the labeled action adds/replaces a stop, clears both fields only after success, and returns focus to latitude. The mobile action spans the full width below the two fields; both fields retain a full keyboard so negative signs remain available. Invalid values stay editable and do not modify the route or map. Address search is not supported.

The header menu offers light, dark, and system themes as a full-width segmented icon row with three equal segments (sun, moon, monitor) below the theme label, with localized accessible names and hover titles, 44px touch targets, and background/border highlighting (without a checkmark) marking the selected option. Left/Right arrows move focus within the row; Enter/Space selects and closes the menu. System appearance is the default and follows OS changes; explicit choices persist under `roamlet-theme` in localStorage. Theme initialization runs before the application paints to avoid a light-theme flash. All surfaces, forms, menus, dialogs, charts, notifications, and map overlays share theme tokens; dark mode reduces raster brightness/saturation and highlights route lines without changing geographic data or requesting different tiles. Switching appearance does not recalculate routes or reset map position. If localStorage is blocked, appearance switching still works for the current session.

Motion is intentionally restrained: short menu/dialog reveals, subtle press feedback, smooth theme-color changes, and an animated mobile sheet. Headings and metrics have no decorative entrance or stagger animations. Initial map loading uses a full-screen branded overlay with an indeterminate orbit/progress animation, theme-aware colors and localized copy. It blocks background interaction and scrolling until the map's `load` event, then restores focus; map errors or a 30-second timeout release it so local workflows stay accessible. Reduced motion disables loader animation. There are no decorative looping animations outside loading states. `client/src/motion.css` centralizes the UI timings; `prefers-reduced-motion` disables UI transitions/animations and map-camera movement animation.

Focus indicators use a consistent high-contrast 2 px ring: coordinate input draws a single ring on its input and library filtering draws one on its container, while standalone fields, keyboard-focused buttons/links, menu items, and map controls retain visible focus. Map/menu rings are inset to avoid clipping, and forced-colors mode uses a system highlight. Radix dialogs initially focus the relevant field (or safe Cancel action), contain keyboard focus, and restore the opener without scrolling; inline library editors/confirmations restore their originating action or the search field if a route was deleted.

ESLint checks code quality; Prettier handles consistent formatting. `eslint-config-prettier` prevents conflicting formatting rules. Use `yarn lint:fix` and `yarn format` before submitting changes; use `yarn lint` and `yarn format:check` for validation.
