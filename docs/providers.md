# Maps and routing providers

[Back to overview](../README.md)

## Routing overview

Automatic routing uses hosted OpenRouteService (ORS) through a same-origin server proxy at `/api/route`. The browser never receives the provider API key. MapLibre GL JS with OpenFreeMap supplies basemaps; manual straight-line planning remains local and independent of ORS and its API key. Only routing requires Vercel Functions; no application database, external draw plugin or offline basemaps are added. Manual geometry uses the existing MapLibre GeoJSON rendering and statistics pipeline. See [service-dependent limitations](planning.md#known-limitations).

## Configuration and providers

| Variable         | Meaning                                                                                                                                        |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `ORS_API_KEY`    | Server-only hosted OpenRouteService key, read from root `.env.local` locally or the Vercel server environment. Never exposed through `VITE_*`. |
| `VITE_MAP_STYLE` | Optional http(s) or root-relative style URL; default `/osm-standard.json` (OpenStreetMap raster tiles)                                         |

MapLibre GL JS uses the Standard OpenStreetMap raster map (OSM Carto) by default, defined in `client/public/osm-standard.json`, with 256-pixel tiles from `https://tile.openstreetmap.org/{z}/{x}/{y}.png` at native zooms 0–19. The Light map remains OpenFreeMap Bright (`https://tiles.openfreemap.org/styles/bright`). Saved Standard preferences use the configured provider (OSM by default); saved Light preferences continue to use Bright. Legacy Custom preferences still load the configured provider, displayed as Standard, and subsequent style selections or camera saves persist it as Standard. Missing or unavailable saved styles retain the OSM fallback and warning. `VITE_MAP_STYLE` replaces the former Mapbox-specific style setting and accepts an `http://`, `https://` or root-relative URL (for example `/styles/custom.json`), not a `mapbox://` URL. Use HTTPS-compatible resources on HTTPS deployments. Resources load browser-direct from OSM, OpenFreeMap or the configured providers, independently of the ORS API key. Preserve the sources' visible attribution, including OpenMapTiles credits for OpenFreeMap.

Follow the [OSM tile usage policy](https://operations.osmfoundation.org/policies/tiles/): retain the browser's HTTP cache and valid Referer, do not deploy a policy that strips cross-origin Referer, and do not add tile prefetching, bulk downloads or offline map features. The service worker does not intercept these external tiles. OSM's donation-funded public tile service and OpenFreeMap offer no SLA; use a suitable provider via `VITE_MAP_STYLE` for deployments whose traffic cannot comply with the public service policy. Automated tests intercept tile requests with synthetic images and do not request public OSM tiles.

The browser uses POST `/api/route` with a `profile` and the existing routing body. The server alone uses POST `https://api.heigit.org/openrouteservice/v2/directions/{cycling-regular|cycling-road|cycling-mountain|foot-hiking}/geojson` with headers `Accept: application/geo+json`, `Content-Type: application/json`, and `Authorization: <API key>`. The GeoJSON endpoint requires the GeoJSON response media type; `Accept: application/json` can return HTTP 406 (ORS code 2007). The JSON body includes `{ "coordinates": [[longitude, latitude], ...], "instructions": false, "elevation": true }`, with `options.avoid_features` when selected. Point alternatives add `alternative_routes: { target_count: 2, weight_factor: 1.4, share_factor: 0.6 }` and require exactly two stops. ORS returns a GeoJSON FeatureCollection with LineString geometry and `properties.summary.distance` / `duration` in metres/seconds. Finite returned heights are retained; absent heights are never fabricated. These parameters are documented in the official [ORS request schema](https://github.com/GIScience/openrouteservice/blob/main/ors-api/src/main/java/org/heigit/ors/api/requests/routing/RouteRequest.java) and [alternative-route schema](https://github.com/GIScience/openrouteservice/blob/main/ors-api/src/main/java/org/heigit/ors/api/requests/routing/RouteRequestAlternativeRoutes.java). Address search, a new backend and offline-map downloads are not added.

**Security and deployment:** `ORS_API_KEY` stays in the server environment. Neither the availability endpoint nor route responses expose it; raw upstream errors and metadata are not forwarded. Actual keys must never be committed. Set Vercel Firewall rate limits before public use and monitor ORS account-wide quotas. Origin checks and client-side caches are not abuse prevention. Provider permissions still require verification; see the [ORS restrictions](https://openrouteservice.org/restrictions/).

### Provider scope

OpenStreetMap supplies the Standard raster basemap and OpenFreeMap supplies the Light vector basemap, both rendered by MapLibre GL JS; hosted OpenRouteService supplies automatic cycling/hiking routes only. New online routes have `source: openrouteservice`. Manual routes have `source: manual` and use local direct segments, independent of routing or API-key configuration. They do not validate road/trail connectivity or access; basemap attribution remains visible, but manual GPX exports contain no routing-provider attribution. Loops remain application-generated with at most six requests. Address/place search is removed from this scope; use coordinates or map clicks/drags. Terrain-RGB fetching, decoding, sampling and caching are entirely excluded. Only imported GPX with complete heights supplies elevation statistics/chart; neither ORS nor legacy Mapbox routes display them, even if old snapshots contain sampled heights.

Automatic routing keeps exact input/profile/options responses in a browser-session cache for five minutes, with up to 50 least-recently-used entries and an 8 MiB serialized UTF-16 data budget. Cache hits do not extend the five-minute lifetime; oversized responses are usable but not cached. Identical in-flight requests share one network call and return independent geometry copies. Cancelling one consumer does not cancel the others; cancelling the last aborts the request, and abandoned late responses and errors are not cached. This cache is not shared across tabs or users. Requests have a 25-second timeout. Point-route edits keep the existing 350 ms debounce; waypoint name/timing changes and identical coordinate replacements do not reroute, while coordinate/order/section-mode/profile changes still recalculate. Name-only undo/redo retains ready geometry and in-flight work. Manual calculations continue to preserve supplied heights. The server availability check is not cached. Cancellation, credential, network and service failures remain actionable, with no automatic straight-line fallback. Manual is a separately selected planning mode, not a fallback for failed routing requests. HTTP 401/403 reports key/account-permission guidance; ORS code 2004 reports service limits. Only ORS codes 2009/2010 are recoverable no-route failures in loop search; code 2011 (incompatible parameters) and generic HTTP 400/422 are service failures, not retried as no-route results. There are no application quota dashboards or quota-recovery controls; Firewall rules must be configured externally. Browser-side bounds and caches do not enforce an account-wide budget. Routing availability, quotas and permitted use depend on the deployed account’s current [ORS terms](https://openrouteservice.org/terms-of-service/) and restrictions. OpenFreeMap’s public basemap service provides no SLA.

**Before publication verify current ORS terms, account eligibility, commercial use, local routing storage/caching, GPX export/redistribution permissions and attribution.** Local storage/export is a product feature, not a legal grant from the provider. Legacy Mapbox snapshots retain their original attribution and remain subject to [Mapbox terms](https://www.mapbox.com/legal/tos); migrating providers does not relicense them. Browser automation uses local synthetic styles/geometry, never production fallback data or real API keys. See [third-party licenses and data policies](../THIRD_PARTY_LICENSES.md).
