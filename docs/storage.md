# Local storage, recovery and backups

[Back to overview](../README.md)

## Saving, recovery and history

- The library and a single current draft are separate IndexedDB records. Debounced draft autosaving retains ordered stops, mode/activity, names, description, current geometry/statistics/source, editable state, route identity and current personal time settings. Loading and request controllers are not serialized. In-memory history and pending autosaves retain immutable editor snapshots and share unchanged geometry rather than cloning the entire track on every edit; IndexedDB writes still capture independent stored data. Pending changes are also flushed when the page becomes hidden; closing a tab cannot guarantee an asynchronous write completes.
- On startup, a draft offers **Restore draft** or **Delete draft**. Recovery does not reroute a ready snapshot, including GPX tracks with disconnected segments and heights. Saving a route or discarding the current work clears its associated draft; late writes/deletes must not replace newer work. Storage errors are reported without disabling the editor.
- Preferences are independent of drafts: map style and camera, language, light/dark/system appearance, activity/mode, loop target, per-activity speeds, stops, planner panels, library search/filters/sort. Camera saves after movement ends, not on animation frames. Existing theme/language/camera storage remains compatible. **Reset settings** requires confirmation and does not delete drafts or library routes.
- Opening a chosen route fits that route; draft recovery restores the editor; ordinary startup uses the last preferences/camera, then existing regional defaults on first use. Geolocation is only requested by the location button. The blue location dot has a translucent accuracy circle whose radius uses the browser-reported accuracy in meters and scales with map zoom; unavailable or invalid accuracy shows only the dot. The circle is updated on each location request and restored when switching map styles. System appearance continues following the OS. Renders and route recalculation do not repeatedly reposition the camera.
- Undo/Redo keeps up to **50 changes** during the current session: adding, deleting, moving, reordering and reversing stops, and geometry-replacing mode changes. A marker drag is one action. New edits clear redo; opening another route or restoring a draft clears session history. Use buttons or **Ctrl/Cmd+Z** and **Ctrl/Cmd+Shift+Z**; text fields retain their native undo. Ready snapshot geometry is restored without a redundant routing request.
- Click an editable, current route line to insert a stop in route order; hovering previews the insertion. Saved/imported snapshots still require explicit conversion before geometry is replaced; disconnected GPX segments are never implicitly joined. Automatic routes support 50 stops, manual drawing 1,000 points. Clicks and taps add points directly when editing is allowed, on both desktop and mobile; no extra add-points toolbar toggle is shown. Existing pins remain draggable, and map dragging does not insert a point.
- Map pins and stop cards share selection. Cards focus the corresponding map point; pins reveal their card and offer explicit replace/remove/start actions. Scale, north reset, direction arrows and scale-dependent distance markers provide orientation without joining separate tracks. Location requests distinguish permission denial, timeout and unavailable position and frame the accuracy area rather than blindly zooming in. Accuracy remains represented by its map circle and accessible geolocation-button description. Elevation, insertion and stale-route labels do not appear as floating map badges; stale status belongs in the planner.
- Recalculation retains the previous route as visibly stale, but disables saving/export and hides outdated statistics until success. Failure, dismissed notices and interrupted requests never make that geometry current. Stale status is persisted in drafts and restored by Undo/Redo; completed matching routes remain available offline.
- Point alternatives use one ORS request for exactly two automatically connected stops. Provider limits and distinct-alternative availability still apply. Selected and inactive alternatives appear together on the map; loop candidates additionally show their absolute difference from the requested length. Disabled alternative actions explain their prerequisites. Cycling, section, fitness and surface choices use the same translated Radix menu styling, keyboard navigation and focus restoration. Calculation and alternative actions share full-width layout. Error cards separate the message, dismiss control and wrapping recovery actions; retries are disabled while busy or offline. Shared typography uses 14px body/control text, 13px labels and 12px supporting text, with larger headings and metrics retained. Mobile text inputs remain 16px to prevent iOS focus zoom; chart ticks use 12px.

Browser storage is not a permanent backup: eviction, private browsing and clearing site data can remove local work. Export important routes and library backups regularly.

## Library backup and organization

“My routes” opens a separate screen with **Back to map**, preserving the mounted editor and its unsaved route. Edit, delete and import confirmations open as overlay dialogs without expanding the route list. Lazy panel loading also overlays the existing layout rather than moving the map. Library routes support favorites, tags, search, activity/favorite/tag/length filters and the existing sorting choices. Filters combine and persist locally; **Reset filters** clears them. Geometry thumbnails are local SVG paths and never connect separate GPX segments. Mobile stop reorder handles have 44px touch areas with unchanged compact icons and keep explicit reorder alternatives. Short-viewport planner/dialog scrolling and readable input sizes are covered by browser emulation; physical iOS Safari and Android Chrome checks remain necessary. Malformed records are reported and skipped in the displayed list, not automatically deleted; valid records remain usable.

**Download backup** downloads JSON with the envelope `{ "version": 1, "exportedAt": "<ISO timestamp>", "routes": [...] }`. Each route contains its supported metadata, geometry segments, heights, original statistics, favorites and tags. Missing older `favorite` and `tags` values default to `false` and `[]`. It excludes the draft, preferences and API keys. Explanations beside the backup actions distinguish JSON library backups from single-route GPX exchange, and state that routes are browser-local with no cloud copy and can be deleted by clearing browser data. Downloading does not claim the file was successfully stored.

**Restore from backup** validates the document and previews its route count before confirmation. Conflicting IDs can be skipped, replaced, or imported as copies (the default); copies receive fresh route and waypoint identifiers. Import is one IndexedDB transaction: invalid data or a storage failure must not leave partial records. Importing the library does not change the open editor.

Backup bounds: **20 MiB per file**, **1,000 routes**, **100,000 points per route**, and **500,000 points overall**. Coordinates, dates, route statistics and the format version are validated. Unsupported versions are rejected. GPX keeps its separate 10 MiB/100,000-point limits.
