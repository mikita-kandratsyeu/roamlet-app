# Route exports and sharing

[Back to overview](../README.md)

## Printable route roadbook

In **Export → Roadbook**, review the A4 portrait sheet and choose **Print roadbook** to open the browser's print dialog. Printing is initiated only by this action. The sheet includes the route name, activity, distance, original time estimate, route map, available elevation profile and ascent/descent, and saved route points in their existing order with names/coordinates and nonzero pauses. The map uses the existing map provider and falls back to a local route outline when basemap tiles are unavailable. No roadbook file is uploaded or sent to a new service.

Elevation is shown only for GPX tracks and routes with confirmed OpenRouteService height provenance. If only some track sections have heights, the profile and climbing totals are labeled as known sections only and preserve gaps; otherwise elevation is clearly unavailable. Route points and pauses are shown only when saved in the route. The roadbook does not generate turn-by-turn directions, infer missing control points or heights, or certify route access or safety. Review the printed sheet before relying on it; estimated durations are not navigation predictions.

## Calendar events (ICS)

In **Route schedule → Export calendar (.ics)**, check the event preview, the IANA time zone at the start and reminder minutes, then select **Download .ics**. This local export works without Google authorization or internet and does not require saving the current route. A complete schedule and positive duration of at most 28 days are required. Supported dates are 1900–2100. Ambiguous or missing daylight-saving departure times are rejected instead of guessed. Event end time uses actual elapsed moving time plus all waypoint pauses, including start and finish; it applies timezone transitions independently of the planner's floating local-clock arrivals.

The file contains one event with the route name, description, distance, total pauses, start-place name and optional reminder. It does not attach GPX or track geometry. Review potentially private names/descriptions before importing or sharing. UTC event times, escaped text and folded UTF-8 lines use the iCalendar format; a calendar app may still create duplicates when importing the same file repeatedly. ICS is an event export, not a route or schedule backup. For optional direct Google publication and manual updates, see [Google Calendar connections](connections.md#google-calendar).

## Route summaries for AI

In **Export → For AI**, review a Markdown request containing structured JSON with route statistics, eligible sustained climbs, personal-time assumptions/ranges and available stop schedules, then press **Copy for AI**. Paste it into an AI chat yourself; no API key, provider connection or automatic network transmission is involved. If clipboard access fails or is unavailable, select and copy the preview manually or retry. Copy success and errors use the shared Sonner notifications, not inline messages in the export dialog. The request follows the interface language (English/Russian); JSON field names and units remain stable.

Names, coordinates and the departure date are excluded by default. Schedules use rounded minutes since local departure, with existing gap/matching limitations; schedule pauses replace aggregate personal stops rather than adding to them. **Include names, coordinates and departure date** explicitly adds the complete segmented track and stop names/coordinates. This option uses a fully clickable checkbox card, including its explanatory text, with a visible checked state and keyboard focus. A separate **Before sharing with AI** notice stays visible whether the option is on or off: review the preview, consider the selected AI service's data handling, and do not treat its answers as a safety assessment. Sharing the track can reveal your home address and travel plans, and even route statistics do not guarantee anonymity. Descriptions, library metadata, account data and keys are never included. Missing metrics remain unavailable, not zero; summaries and AI responses do not establish route safety. Export does not change saved routes or GPX.

## Route images for social media

In **Export → For social media**, configure a title, post (1080 × 1350), story (1080 × 1920) or square (1080 × 1080) format, light/dark image theme and visible statistics, then press **Create preview**. Choose **Minimalism**, **Adventure** or **Relief** through illustrative template thumbnails, and a forest-green, lake-blue or sunset-orange accent. Relief is available only with complete eligible heights and shows a profile of original visible track points, preserving gaps without inventing elevations at privacy cuts. Story compositions reserve 250 px at the top and bottom for social-app overlays; **Show story safe zones** adds preview-only guides, never exported pixels. These margins are guides, not a guarantee for every platform. After the first generation, title, template, color, theme and statistics changes refresh the preview after a short debounce; format, privacy radius and geometry changes still require **Create preview**. Cancellation stops automatic refresh until generation is requested again. Design, format, metric choices and valid privacy radius are saved in local preferences on this device, not the title or track; unavailable stored Relief settings fall back to Adventure for routes without eligible elevations. **Publication caption** contains the title, planned-route/activity labels and selected statistics, without coordinates or invented accomplishments. **Copy caption** copies only on a click; a read-only text preview remains available for manual copying if clipboard access fails. The export editor places settings and preview side by side on desktop and stacks them on smaller screens. Template, color, format, theme and privacy controls share equal-width segmented buttons, consistent selected/focus states and 44 px minimum targets; color swatches stay aligned when labels wrap. The placeholder reserves the selected image's aspect ratio and preview size to avoid a layout jump when generation completes; progress appears in the preview with an accessible status below it. Its header, export-mode selector and action footer stay outside the scrolling content, so controls never cover the image. The footer divider spans the dialog's inner width, while a separate right-hand scrollbar lane leaves clearance around settings and preview. Privacy details are collapsed initially, with a short always-visible radius explanation. The PNG uses a soft gradient and decorative contour lines, a compact Roamlet app icon with a vertically centered wordmark and a planned-route badge on the opposite side, a visually dominant route title, a lightweight cycling/hiking icon beside the activity label, and an outlined statistics panel with vertical column dividers, centered labels and larger auto-fitted values. Badge, wordmark and activity text are centered using the visible glyph bounds rather than font-box offsets. Each statistics row uses equally sized cells, including an incomplete last row, with balanced label/value spacing for one- and two-line labels. Dark cards use a light brand tile to separate the icon from the background. The route uses a thicker, contrast-cased line and distinct start/finish markers when privacy is disabled. The contour background is decorative, not an elevation or terrain map. Time is an optional original estimate, not a recorded activity; elevation gain is offered only when complete, eligible heights and a finite metric are available. Route segment gaps remain gaps. No basemap, photo upload, account, routing request or external image service is used.

**Hide around start and finish (metres)** accepts a radius from 0 to 10000, with full-track, 200 m, 500 m and 1000 m presets. An always-visible publishing notice indicates whether the full track or hidden endpoint zones are selected and warns that the title can disclose a location. Zero shows the complete track. A positive radius hides route portions around both original endpoints, including later revisits and crossing edges, and omits endpoint markers. If nothing remains visible, reduce the radius and retry. Raster protection conservatively hides some extra area around the protected circles. Ambiguous polar, antipodal or repeatedly globe-wrapping privacy geometry is rejected rather than rendered with uncertain protection. Only the image is affected: saved geometry, title, statistics and GPX remain unchanged. Statistics describe the full route, not just the visible outline. Check the title and generated image before publishing; this feature does not guarantee anonymity.

Geometry processing, drawing and PNG encoding run in a short-lived module worker with `OffscreenCanvas` where supported. Browsers without this capability use a yielded Canvas compatibility path on the main thread, which may be less responsive for large tracks. Generation can be cancelled, obsolete results are ignored, and workers and preview URLs are released on changes or close. **Download PNG** reuses the generated image. **Share image** appears only when the browser supports sharing PNG files through the system menu, and shares only after a user click. Cancelling sharing is silent; a sharing failure leaves downloading available. After the production app shell is cached, image generation also works on the first offline visit to this export mode.
